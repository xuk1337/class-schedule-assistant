## 三、正式前后端边界

正式课表前端位于 `班级课表助手_正式系统/static/index.html`，系统管理前端位于
`班级课表助手_正式系统/static/admin.html`。两者均通过 `static/js/api.js`
访问 Flask API，并遵循以下边界：

- 页面不硬编码正式账号、密码、班级或邀请码；
- 不使用 `localStorage` 保存账号、课程、作业或权限；
- 密码哈希、Session、CSRF、角色和班级权限全部由 Flask 处理；
- 按钮可见性仅用于改善体验，不能替代服务端鉴权；
- `role`、`class_id` 和 `semester_id` 的有效范围由服务端从 Session 和数据库推导；
- 双 CSV 由服务端统一解析、校验并在 SQLite 事务中覆盖。

SQLite 是唯一权威业务数据源。开发环境测试数据由种子脚本生成，生产环境不显示
固定凭证或邀请码。

## 五、前后端联调约定

- JSON 字段使用 `snake_case`；日期为 `YYYY-MM-DD`；时间戳为带时区 ISO 8601。
- 所有错误使用 `{"code","message","details"}`，前端按 `code` 处理，不解析文案判断业务。
- 前端先调用 `GET /api/auth/me` 恢复身份，再加载业务数据。
- 班级和当前学期范围由后端从 Session 与数据库推导，业务写接口不接受前端扩大范围。
- 401 跳转登录，403 显示无权限，409 保留表单并展示冲突详情，500 显示请求 ID。
- 写请求携带 CSRF；批量导入使用 `multipart/form-data` 同时上传两份 CSV。
- 课程详情返回课程基本信息、`sessions` 数组和 `homework` 数组。
- 邀请码重新生成接口的明文只允许在成功响应中展示一次，不写入前端持久化存储。
