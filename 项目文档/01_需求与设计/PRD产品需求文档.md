## 1. 项目背景与目标

### 1.1 背景

大学生每学期课表分散在教务系统、截图、聊天记录里，同学之间经常互相询问「明天第几节有课」「在哪上课」「作业什么时候截止」「还有几天考试」。教务系统课表不支持个人化的作业、考试、备注管理，也不方便在同学之间分享同一套班级课表。

### 1.2 目标

做一个轻量的班级课表管理与课程提醒工具，满足：

1. 一班一表、全班共用：系统管理员先创建班级并导入学生名单，学生凭学号、姓名和班级邀请码激活账号，登录后查看本班统一课表与作业；
2. 课表即提醒：在课表页直接看到「距离最近考试还有几天」「哪些作业快到期/已逾期」；
3. 管理集中高效：班级管理员一次选择课程、作业两份 CSV，统一校验并原子覆盖本班课程与作业；
4. 数据按班隔离：管理员只能维护所属班级，学生只能查看所属班级，不同班级互不影响；
5. 便于留存打印：所有已登录用户均可将当前周课表导出为横向 PDF；
6. 录入不出错：手工添加或 CSV 导入时均校验节次、周次、日期和课程时间冲突；
7. 身份可追溯：班级、学生名单和班级管理员均有明确来源，邀请码动态生成且可失效，关键管理操作写入审计日志；
8. 模型可扩展：课程信息与上课安排分开存储，同一课程编号可对应多个上课时段，作业统一关联课程。

正式系统按学期保存课表，学期包含名称、第一周周一日期、周数和状态。首期界面只开放当前学期，历史学期数据保留但暂不提供前台切换。

### 1.3 实现边界说明

正式课表入口为 `班级课表助手_正式系统/static/index.html`，系统管理入口为
`班级课表助手_正式系统/static/admin.html`。页面数据全部通过 Flask API 获取，
SQLite 是唯一权威业务数据源；认证、鉴权、业务校验和事务均由服务端执行，前端
不通过硬编码账号、邀请码、角色或 `class_id` 决定权限。

## 2. 用户角色与权限授予

| 用户角色 | 特征描述 | 核心诉求 | 使用频率 | 登录凭证 |
| --- | --- | --- | --- | --- |
| 班级同学（学生） | 已在班级名单中的在校学生，激活后只读访问所属班级数据 | 查看本周课程、教室、考试和作业提醒，导出 PDF | 每日多次 | 学号 + 密码 |
| 学习委员/课代表（班级管理员） | 由辅导员或班主任确认，负责维护本班统一课程与作业 | 双 CSV 导入、冲突检测、课程和作业维护、邀请码重置 | 每周1-2次（开学季频繁） | 系统管理员分配并绑定班级的管理员账号 + 密码 |
| 系统管理员 | 学校或项目运维人员，负责系统级基础数据与账号生命周期 | 创建学期和班级、导入学生名单、任命/交接班级管理员、停用账号、重置密码、查看审计日志 | 按需 | 部署时通过受控命令创建的系统管理员账号 + 密码 |

### 2.1 班级管理员身份来源

班级管理员身份不由系统自动推断，也不能由学生申请或通过邀请码获得。辅导员或班主任确认人选，并向系统管理员提供班级代码、姓名、登录账号和生效时间。系统管理员在受保护的管理后台完成任命或交接。

`users.role` 取值为 `student`、`admin`、`system_admin`；`users.status` 取值为 `pending`、`active`、`disabled`。班级管理员必须同时满足 `role='admin'`、`class_id` 匹配、`status='active'` 才能执行本班写操作；系统管理员的 `class_id` 为空。`classes` 表不重复保存管理员姓名，每个班级默认只允许一个有效班级管理员。

### 2.2 班级、学生与邀请码来源

1. 系统管理员创建学期和班级，并导入由辅导员或班主任确认的学生名单。
2. 导入后在 `users` 表生成 `role='student'`、`status='pending'` 的待激活记录，学号全系统唯一，密码为空。
3. 系统使用安全随机数生成班级邀请码，只保存摘要 `invite_code_hash`；明文仅在生成或重新生成时展示一次，由班级管理员线下发放。
4. 学生注册时必须同时匹配邀请码对应班级、待激活学号和姓名，成功后写入密码哈希并将状态改为 `active`。
5. 班级管理员可重新生成邀请码；新码生效后旧码立即失效，已激活账号和班级业务数据不受影响。
6. 学生转班、离校、账号停用和密码重置由系统管理员处理并记录审计日志，学生不能自行修改 `class_id` 或角色。

## 3. 用户故事

| 用户故事编号 | 角色 | 场景描述 | 期望结果 |
| --- | --- | --- | --- |
| US-001 | 学习委员 | 开学第一周，需要录入本班完整课程与作业 | 下载课程、作业两份 CSV 模板并一次选择导入；系统统一校验，确认后在同一事务中覆盖本班原课程与作业 |
| US-002 | 班级同学 | 首次使用系统，需要激活自己的预置学生记录 | 输入真实姓名、学号、班级邀请码和密码；系统匹配待激活名单后启用账号并绑定班级 |
| US-003 | 班级同学 | 周三晚上查看课表，了解近期考试和作业安排 | 顶部提醒区显示考试倒计时和作业状态，逾期标红、即将到期标橙 |
| US-004 | 班级同学 | 明天有课，想快速查看明天的课程安排 | 切换到日视图，选择周四，按节次顺序清晰展示当天所有课程的时间、教室、教师 |
| US-005 | 学习委员 | 需要发布、修改或删除某门课程的全班作业 | 点击课程进入详情，完成作业增删改后，全班学生看到相同内容且提醒区即时更新 |
| US-006 | 学习委员 | 发现某门课程时间有误，需要修改 | 进入课程详情，点击编辑，修改时间后保存；若与其他课程冲突则提示并拒绝保存 |
| US-007 | 班级同学 | 需要快速找到某门课程的上课地点 | 使用搜索框输入课程名，周视图/日视图实时过滤显示匹配课程 |
| US-008 | 班级同学 | 需要留存或打印当前周课表 | 点击「导出PDF」，在浏览器打印窗口选择「另存为 PDF」，得到包含班级和周次的横向课表 |
| US-009 | 系统维护人员 | 收到辅导员或班主任确认的管理员名单，或班级管理员发生换届 | 按名单预置新账号并绑定班级；交接时停用旧账号、启用新账号，班级课程、作业和学生数据保持不变 |
| US-010 | 系统管理员 | 新学期需要初始化基础数据 | 创建学期和班级、导入学生名单、任命班级管理员并生成班级邀请码 |
| US-011 | 班级管理员 | 邀请码疑似泄露 | 重新生成邀请码并获得一次性明文，旧邀请码立即失效，已注册学生不受影响 |
| US-012 | 学习委员 | 同一门高等数学每周有两个上课时段 | 使用同一个课程编号保存课程，并为该课程维护周一、周三两条上课安排；作业只需关联一次课程 |

## 5. 页面流程

### 5.1 页面结构说明

正式产品包含课表单页应用和系统管理后台：

**登录页（首屏）**：用户打开页面首先进入登录页，包含：
- 品牌区：「📚 班级课表助手」Logo + 标题 + 副标题
- 角色切换 Tab：🎓 学生登录 / ⚙️ 班级管理员
- 表单区：学号/管理员账号输入框 + 密码输入框（含 👁️ 可见切换）
- 登录按钮：点击后验证账号密码，成功则跳转课表主页
- 学生注册入口：学生登录 Tab 下显示「立即注册」；注册表单包含姓名、班级邀请码、学号、密码、确认密码，邀请码自动映射班级
- 管理员注册说明：管理员 Tab 不提供注册入口，显示「账号由辅导员或班主任确认后，由系统维护人员预置」
- 错误提示：账号密码错误时显示红色提示
- 生产环境不展示测试账号或固定邀请码；开发环境测试数据由种子脚本生成

**课表主页（登录后）**：
- 顶部 Header：标题、搜索框、用户信息区（角色标签 + 班级 + 账号 + 退出按钮）、「＋ 添加课程」「课程模板」「作业模板」「导入课程+作业」（仅管理员可见）和「导出PDF」；
- 班级上下文：显示当前班级名称与「全班同学共享同一份课表，由本班管理员统一维护」；
- 提醒区 Banner：考试倒计时卡片 + 作业提醒卡片；
- 主区域：周次导航（◀ 第 N 周 ▶ + 周/日视图切换 + 日视图的星期选择器）+ 周视图表格 / 日视图列表；
- 弹窗层：课程编辑表单弹窗、课程详情弹窗、Toast 轻提示。

**系统管理后台（仅 `system_admin`）**：
- 学期管理：名称、第一周周一、周数、启用状态；
- 班级管理：班级代码、班级名称、所属学期、状态；
- 学生名单：CSV 导入、待激活/已启用/已停用状态、转班和停用；
- 管理员管理：任命、交接、停用和初始密码重置；
- 审计日志：按操作者、班级、动作和时间查询。

```

    A[打开课表应用] --> L[登录页]
    L --> L0{学生账号已激活?}
    L0 -- 否 --> R1[填写姓名/学号/邀请码/密码]
    R1 --> R2{邀请码、班级和待激活名单匹配?}
    R2 -- 否 --> R1
    R2 -- 是 --> R3[写入密码哈希并将状态改为active]
    R3 --> L
    L0 -- 是/管理员 --> L1[输入账号和密码]
    L1 --> L2{Session、status和role验证}
    L2 -- 失败 --> L
    L2 -- 学生或班级管理员 --> E[按class_id与当前semester加载数据]
    E --> F[浏览: 切换周次 / 周日视图 / 搜索关键词]
    E --> X{role=admin且class_id匹配?}
    X -- 是 --> C1[下载课程和作业 CSV 模板]
    C1 --> C2[一次选择两份 CSV]
    C2 --> C3{统一校验表头/关联/范围/日期/冲突}
    C3 -- 失败 --> C4[整体回滚, 原课程与作业不变]
    C3 -- 通过 --> C5[confirm 整体覆盖本班数据]
    C5 -- 确认 --> C6[事务覆盖当前class_id和semester_id]
    X -- 是 --> G[点击 添加课程]
    G --> H1[填写课程编号/名称/教师/考试日期/备注]
    H1 --> H2[添加一条或多条教室/星期/节次/周次安排]
    H2 --> I{保存: 前端校验}
    I -- 未通过 --> H1
    I -- 通过 --> J{时间冲突检测}
    J -- 冲突 --> K[toast 与某课程时间冲突] --> H2
    J -- 通过 --> W[保存到本班并刷新课表]
    E --> M[点击课程色块]
    M --> N[课程详情弹窗: 信息 + 班级作业列表]
    N --> N1{是否班级管理员?}
    N1 -- 是 --> O[添加/编辑/删除作业] --> P[全班作业与提醒即时刷新]
    N1 -- 是 --> Q[编辑课程或上课安排] --> H1
    N1 -- 是 --> R[删除课程: confirm 后删除]
    N1 -- 否 --> N2[只读查看]
    E --> S[点击导出PDF]
    S --> T[横向打印当前班级当前周课表]
    T --> U[浏览器选择另存为 PDF]
    E --> V[点击退出]
    V --> L
```

## 6. 交互规则

### 6.1 冲突检测规则（服务端，新增/编辑上课安排时触发）

| 规则项 | 判定逻辑 |
| --- | --- |
| 冲突范围 | 相同 `class_id` 和 `semester_id` 下的 `course_sessions`，编辑时排除当前上课安排 id |
| 冲突条件 | 同一星期（day 相同）**且** 节次区间重叠（已有.start_slot ≤ 新.end 且 已有.end_slot ≥ 新.start）**且** 周次区间重叠（已有.week_start ≤ 新.weekEnd 且 已有.week_end ≥ 新.weekStart） |
| 处理结果 | 命中冲突 → 返回 HTTP 409，body 为 `{"error": "与《课程名》时间冲突！"}`，数据不落库；前端 toast 该信息，表单保持打开供修改 |
| 编辑豁免 | 编辑上课安排时与自身比对不计冲突 |
| 前置校验 | 课程名空 → 400「课程名不能为空」；节次/周次非数字 → 400「节次/周次参数格式错误」；星期不在 1–7 → 400；开始节次 > 结束节次 → 400；起始周 > 结束周 → 400（前端在提交前对后两项同样拦截） |

### 6.2 作业提醒着色规则（前端，以当天日期为基准）

| 状态 | 条件（left = 截止日 − 今天，单位天） | 样式 | 文案 |
| --- | --- | --- | --- |
| 已逾期 | left < 0 | 红色加粗 | 已逾期 N 天 |
| 即将到期 | 0 ≤ left ≤ 2 | 橙色 | 剩 N 天 |
| 正常 | left > 2 | 默认色 | 剩 N 天 |

作业提醒卡片按截止日期升序排列，最多展示 5 条；课程详情内作业列表同样按此规则着色。

### 6.3 周次过滤规则

| 场景 | 规则 |
| --- | --- |
| 当前周计算 | `floor((今天 - semester.start_date) / 7) + 1`；早于学期开始取第 1 周，晚于学期结束取最后一周 |
| 周视图/日视图渲染 | 仅显示 `week_start ≤ 当前周 ≤ week_end` 的上课安排 |
| 周次切换 | 范围为 `1–semester.week_count`，越界钳制 |
| 导出 PDF | 固定打印当前周在周的完整周视图，即使页面当前处于日视图也不影响 |
| 表头日期 | `semester.start_date + (当前周-1)×7 + 星期偏移`，不得以浏览器打开当天作为第 1 周基准 |

| 注册校验 | 服务端校验邀请码摘要、班级状态、待激活学号、姓名和班级必须一致；已激活、已停用或不在名单中的学号拒绝注册 |

### 6.5 班级管理员认定与交接规则

| 规则项 | 说明 |
| --- | --- |
| 人选确认 | 由辅导员或班主任依据班级实际分工在系统外确认，并向系统管理员提供班级代码、管理员姓名、登录账号和生效时间；邀请码或学生自报信息不能授予权限 |
| 账号创建 | 系统管理员依据确认名单创建管理员账号；密码只保存哈希，公开 API 不提供管理员注册或角色升级入口 |
| 数据库标识 | `users.role='admin'` 表示班级管理员，`users.class_id` 表示负责班级，`users.status='active'` 表示账号有效；三项必须同时满足才允许本班写操作 |
| 唯一性 | 每个班级默认只允许一个 `status='active'` 的管理员；由服务端校验并通过 SQLite 条件唯一索引约束，防止重复授权 |
| 权限边界 | 管理员只能维护自身 `class_id` 的课程、作业、邀请码和双 CSV 导入；不能修改自己的角色、班级归属或其他用户权限 |
| 换届交接 | 辅导员或班主任确认新管理员后，由系统管理员在同一事务中停用旧账号并创建或启用新账号；旧账号立即失去登录和写权限 |
| 数据继承 | 课程、作业、学生及邀请码均归属于班级而非管理员个人，管理员交接不迁移、不删除班级数据 |
| 审计 | 任命、交接、停用和密码重置均记录系统管理员、目标账号、班级、时间和结果 |

### 6.6 课程与作业双 CSV 整体导入规则

| 规则项 | 说明 |
| --- | --- |
| 权限与范围 | 仅班级管理员可操作；两份 CSV 均不填写班级列，自动归属当前管理员绑定班级 |
| 课程表头 | `课程编号,课程名,教师,教室,星期,开始节次,结束节次,起始周,结束周,考试日期,备注` |
| 作业表头 | `课程编号,作业内容,截止日期`；`课程编号` 必须引用同批课程 CSV 中存在的课程 |
| 基础限制 | 必须一次选择两份 `.csv`；每个文件不超过 2MB；课程最多 100 行、作业最多 300 行；支持 UTF-8 BOM、双引号及字段内逗号 |
| 课程编号 | 同一课程编号允许在课程 CSV 中出现多行，每行表示一条上课安排；相同编号的课程名、教师、考试日期和备注必须一致 |
| 格式范围 | 课程编号仅允许字母、数字、`_`、`-`；星期 1–7；节次 1–12；周次不得超过当前学期周数；非空日期必须为有效 `YYYY-MM-DD` |
| 唯一性 | 课程在班级和学期内按课程编号唯一；上课安排按课程、星期、节次和周次组合去重；同课程同内容同截止日期的作业不得重复 |
| 完整校验 | 服务端重新解析并校验两份表头、课程级字段一致性、必填字段、作业关联、日期、范围与上课时间冲突；前端校验仅用于即时提示 |
| 覆盖与回滚 | confirm 明示覆盖当前班级当前学期全部课程、上课安排和作业；服务端在同一事务中先删后写，失败整体回滚，不影响其他班级或学期 |

### 6.8 正式 API 契约

| 模块 | 主要接口 | 权限与约束 |
| --- | --- | --- |
| 认证 | `POST /api/auth/student-activate`、`POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/me`、`POST /api/auth/change-password` | 激活仅处理待激活学生；登录成功建立 Session；所有写请求校验 CSRF |
| 系统管理 | `POST /api/system/semesters`、`POST /api/system/classes`、`POST /api/system/classes/{id}/students/import` | 仅 `system_admin`；名单导入使用事务并返回逐行错误 |
| 账号管理 | `PUT /api/system/classes/{id}/admin`、`PATCH /api/system/users/{id}`、`POST /api/system/users/{id}/reset-password` | 仅 `system_admin`；任命、交接、转班、停用和重置均写审计日志 |
| 邀请码 | `POST /api/classes/me/invite-code/regenerate` | 仅当前班级有效管理员；返回一次性明文，数据库只保存摘要 |
| 课表查询 | `GET /api/schedule?week=N`、`GET /api/courses/{id}` | 学生和班级管理员仅查询自身班级当前学期 |
| 课程管理 | `POST /api/courses`、`PUT /api/courses/{id}`、`DELETE /api/courses/{id}` | 仅班级管理员；课程编号在班级和学期内唯一 |
| 上课安排 | `POST /api/courses/{id}/sessions`、`PUT /api/course-sessions/{id}`、`DELETE /api/course-sessions/{id}` | 仅班级管理员；服务端执行时间冲突检测 |
| 作业管理 | `POST /api/courses/{id}/homework`、`PUT /api/homework/{id}`、`DELETE /api/homework/{id}` | 仅班级管理员；学生写请求返回 403 |
| 批量导入 | `POST /api/import/course-homework` | 仅班级管理员；两份文件统一校验并事务覆盖当前班级当前学期 |
| 审计查询 | `GET /api/system/audit-logs` | 仅 `system_admin`；支持操作者、班级、动作和日期筛选 |

统一响应规则：成功返回 JSON 和适当的 `200/201/204`；参数错误返回 `400`，未登录返回 `401`，无权限返回 `403`，资源不存在返回 `404`，业务冲突返回 `409`，服务端异常返回 `500`。错误体统一为 `{"code":"ERROR_CODE","message":"可读提示","details":{}}`，不得返回堆栈、密码哈希或邀请码明文。

接口字段统一使用 `snake_case`，日期使用 `YYYY-MM-DD`，时间戳使用带时区的 ISO 8601 字符串。资源 ID 由服务端生成；前端不得提交 `role`、授权范围内的 `class_id` 或审计字段来覆盖服务端上下文。列表接口统一支持 `page`、`page_size`，响应包含 `items`、`page`、`page_size`、`total`。

### 6.9 正式数据模型

SQLite 开启外键约束，迁移脚本负责建表和索引。正式系统目标包含以下 9 张表：

| 表名 | 关键字段 | 关系与约束 |
| --- | --- | --- |
| `semesters` | `id`、`name`、`start_date`、`week_count`、`status`、时间戳 | `start_date` 必须为周一，`week_count` 为 1–30；同一时刻只允许一个 `active` 学期 |
| `classes` | `id`、`class_code`、`class_name`、`invite_code_hash`、`invite_code_updated_at`、`status`、时间戳 | `class_code` 全局唯一；只保存邀请码摘要；班级停用后禁止新激活和业务写入 |
| `users` | `id`、`login_id`、`student_no`、`name`、`password_hash`、`role`、`status`、`class_id`、时间戳 | `login_id` 全局唯一，学生 `student_no` 全局唯一；待激活学生密码为空；`student/admin` 必须绑定班级，`system_admin.class_id` 必须为空 |
| `teachers` | `id`、`name`、时间戳 | 教师姓名用于联想；删除前必须确认无课程引用 |
| `time_slots` | `section_no`、`start_time`、`end_time` | 保存第 1–12 节的显示时间，`section_no` 唯一 |
| `courses` | `id`、`class_id`、`semester_id`、`course_code`、`course_name`、`teacher_id`、`exam_date`、`remark`、时间戳 | `class_id + semester_id + course_code` 唯一；课程删除级联删除上课安排和作业 |
| `course_sessions` | `id`、`course_id`、`classroom`、`day_of_week`、`start_section`、`end_section`、`week_start`、`week_end`、时间戳 | 一门课程可有多条安排；星期、节次、周次满足范围和起止顺序；服务端做跨课程冲突检测 |
| `homework` | `id`、`course_id`、`content`、`deadline`、`created_by`、`updated_by`、时间戳 | 作业属于课程并随课程删除；本期不保存学生个人完成状态 |
| `audit_logs` | `id`、`actor_user_id`、`action`、`target_type`、`target_id`、`class_id`、`result`、`detail_json`、`created_at` | 只追加不修改；记录关键管理动作，不记录密码、密码哈希或邀请码明文 |

必须建立的数据库约束包括：外键约束、课程编号联合唯一索引、学生学号唯一索引、每班一个有效管理员的条件唯一索引，以及一个有效学期的条件唯一索引。`class_id` 和 `semester_id` 的访问范围仍由服务端从 Session 推导，数据库字段存在不代表前端可自行指定。

## 7. 边界条件

| 场景 | 边界情况 | 预期处理 |
| --- | --- | --- |
| 学生注册 | 姓名、班级邀请码、学号或密码未填写完整 | 前端拦截，提示「请完整填写注册信息」 |
| 学生注册 | 班级邀请码不存在或已停用 | 拒绝注册，提示「班级邀请码无效，请向班级管理员确认」 |
| 学生注册 | 邀请码有效，但学号和姓名不在该班待激活名单中 | 拒绝激活，统一提示「注册信息与班级名单不匹配」，不泄露其他班级或账号信息 |
| 学生注册 | 学号状态为 `active` 或 `disabled` | 已激活账号提示直接登录；停用账号提示联系系统管理员，不允许重新注册 |
| 学生注册 | 学号不是 6–20 位数字 | 前端拦截，提示「学号应为 6-20 位数字」 |
| 学生注册 | 密码少于 8 位或两次输入不一致 | 前端拦截并显示对应错误提示，服务端再次校验 |
| 学生注册 | 数据库写入失败 | 回滚激活事务，不写入密码哈希且不建立登录会话 |
| 管理员授权 | 学生尝试注册管理员账号、修改 `role` 或直接调用管理员写接口 | 拒绝请求，不修改账号角色；未登录返回 401，已登录但无权限返回 403 |
| 管理员登录 | 管理员账号已停用或未绑定班级 | 拒绝登录或拒绝创建有效会话，不加载任何班级管理数据 |
| 管理员交接 | 新旧管理员同时被设置为有效 | 事务和唯一约束阻止保存；必须先停用旧账号，再启用新账号 |
| 管理员交接 | 旧账号停用、新账号启用成功 | 新账号继承本班管理权限；原课程、作业、学生和邀请码保持不变 |
| 邀请码重置 | 两名管理员或重复请求同时重置 | 服务端串行执行，以最后一次成功事务生成的邀请码为准，之前的邀请码全部失效 |
| 邀请码重置 | 生成成功 | 数据库只保存摘要，明文仅在响应中展示一次，审计日志不得记录明文 |
| 学生转班 | 目标班不存在、已停用或学号冲突 | 拒绝转班并保持原数据；成功时只更新学生 `class_id`，不复制原班课表数据 |
| 学期配置 | 第一周周一不是星期一、周数不在 1–30 | 拒绝保存并提示具体字段错误 |
| 课程录入 | 课程名为空 | 前端拦截，提示「课程名不能为空」，表单不提交 |
| 课程录入 | 教师名或教室为空 | 前端拦截，提示完整填写课程信息 |
| 课程录入 | 节次/周次为非数字 | 前端拦截，提示「请输入有效数字」 |
| 课程录入 | 星期不在 1–7 范围 | 前端下拉选择限制，服务端二次校验返回 400 |
| 课程录入 | 开始节次 > 结束节次 | 前端拦截，提示「开始节次不能大于结束节次」 |
| 课程录入 | 起始周 > 结束周 | 前端拦截，提示「起始周不能大于结束周」 |
| 课程录入 | 上课安排结束周超过学期周数 | 服务端返回 400，不保存 |
| 课程录入 | 与已有课程时间冲突 | 服务端返回 409，前端 toast 提示并保持表单打开 |
| 周次切换 | 当前周为第 1 周点击 ◀ | 无操作，周次保持为第 1 周 |
| 周次切换 | 当前周为学期最后一周点击 ▶ | 无操作，周次保持为最后一周 |
| 考试倒计时 | 无未来考试安排 | 提示「暂无考试安排」 |
| 考试倒计时 | 考试日期为今天 | 显示「还有 0 天」 |
| 作业提醒 | 当前班级无作业 | 提示「暂无作业」；本期不提供学生个人完成状态 |
| 作业提醒 | 作业数量超过 5 条 | 仅显示截止日期最早的 5 条 |
| 搜索课程 | 搜索关键词无匹配 | 周视图/日视图显示空白，提示「未找到匹配课程」 |
| CSV 导入 | 未同时选择两份 `.csv` 或任一文件超过 2MB | 拒绝读取，提示同时选择课程和作业文件并检查大小 |
| CSV 导入 | 表头、字段、范围、日期、课程编号关联或重复作业无效 | 提示具体错误；课程与作业均不保存 |
| CSV 导入 | 同一课程编号多行的课程名、教师、考试日期或备注不一致 | 拒绝整批导入并指出冲突行 |
| CSV 导入 | 文件内课程时间冲突 | 拒绝整批导入；本班原课程与作业保持不变 |
| CSV 导入 | 校验通过但用户取消覆盖 | 不修改本班原课程与作业 |
| CSV 导入 | 删除旧数据后写入失败 | SQLite 事务整体回滚，本班原课程与作业保持不变 |
| 删除课程 | 课程关联有上课安排或作业 | 确认框显示关联数量；确认后由外键级联删除 |
| 删除课程 | 误触删除按钮 | 弹出二次确认，确认后才执行删除 |
| PDF 导出 | 当前周无课程 | 仍输出包含班级、周次、星期和节次表头的空课表 |
| 空状态 | 学生所在班级无课表 | 提示「本班暂无课程，请联系班级管理员导入」 |
| 空状态 | 管理员所在班级无课表 | 提示「本班暂无课程，请导入课程与作业 CSV」 |

### 8.4 系统管理后台

系统管理后台与课表主页路由分离，只允许 `system_admin` 进入。桌面端采用左侧导航和右侧数据表格，至少包含：

| 页面 | 列表信息 | 主要操作 |
| --- | --- | --- |
| 学期管理 | 名称、第一周周一、周数、状态 | 新建、启用、停用；启用新学期需二次确认 |
| 班级管理 | 班级代码、班级名称、状态、有效管理员 | 新建、停用、查看名单、生成初始邀请码 |
| 学生名单 | 姓名、学号、班级、激活状态 | CSV 导入、转班、停用、重置密码 |
| 管理员管理 | 姓名、账号、负责班级、状态 | 任命、交接、停用、重置初始密码 |
| 审计日志 | 时间、操作者、动作、目标、班级、结果 | 条件筛选和分页查看，不提供修改或删除 |

涉及停用、交接、重置密码和生成邀请码的操作均使用确认弹窗，成功后刷新列表；失败时保留用户筛选和分页位置。

| 数据一致性 | SQLite 为唯一业务数据源，前端缓存不得决定账号、角色、班级、课程或作业 | 刷新或更换浏览器后数据一致；事务失败无部分写入；开启 `PRAGMA foreign_keys=ON` |
| 认证与授权 | Session、CSRF、密码哈希、账号状态和服务端角色鉴权同时生效 | 越权测试覆盖学生写入、跨班访问、停用账号和伪造 `class_id`，均返回 401/403 且数据不变 |
| 密码与邀请码安全 | 使用 Werkzeug 密码哈希；邀请码使用密码学安全随机数并只保存摘要 | 数据库、响应历史和审计日志中无密码明文、密码哈希泄露或邀请码明文留存 |
| Web 安全 | Cookie 设置 `HttpOnly`、`SameSite=Lax/Strict`，生产环境启用 `Secure`；所有输出转义；登录限流 | 通过 CSRF、XSS、会话固定、暴力登录和错误信息泄露测试 |
| 性能 | 典型班级不超过 100 门课程、300 条作业；常用查询避免 N+1 | 本地验收环境中课表查询和普通写接口 P95 小于 500ms，批量导入 2MB 内文件小于 5s |
| 并发与可靠性 | 写操作使用短事务；批量覆盖、管理员交接和邀请码重置具备原子性 | 并发测试无重复有效管理员、无半批导入；数据库锁冲突返回可读错误并可重试 |
| 可用性与响应式 | Chrome、Edge 最新两个主版本以及 360px 以上移动视口可用 | 主要流程可用键盘操作；表单标签和错误提示可识别；移动端课表可横向浏览 |
| 可观测性 | 记录请求 ID、错误和关键管理审计；日志不含敏感明文 | 500 错误可按请求 ID 定位；审计可查询操作者、目标、时间和结果 |
| 备份恢复 | 部署方定期备份 SQLite 数据库，恢复过程有文档 | 在测试环境完成一次备份恢复演练，恢复后外键检查通过且关键记录数量一致 |
| 部署配置 | 开发、测试、生产配置分离；密钥和数据库路径由环境变量提供 | 生产环境关闭 Flask debug，不使用默认密钥或源码中的固定账号；通过 WSGI 服务启动 |
| 可维护性 | 数据库迁移、种子数据、接口测试和业务测试纳入仓库 | 全新数据库可由迁移初始化；开发种子脚本不得在生产自动执行 |
