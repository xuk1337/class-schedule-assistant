# 班级课表助手项目需求搜集清单

| 项目 | 内容 |
|---|---|
| 项目名称 | 班级课表助手 |
| 清单用途 | 记录需求来源、目标用户、确认结果、优先级和验收证据 |
| 需求基线 | PRD v2.0 |
| 当前状态 | 核心需求已实现并完成本地验收，生产发布项待验证 |
| 整理日期 | 2026-08-08 |

## 一、需求搜集方式与来源

本项目为实训项目，需求通过任务要求梳理、业务规则确认、原型评审、PRD评审、代码联调
和测试反馈逐步形成。当前没有开展真实生产用户问卷或大规模访谈，本文不会将小组讨论
或测试反馈表述为正式用户调研。

| 来源编号 | 需求来源/方式 | 主要产出 | 可追溯材料 |
|---|---|---|---|
| S01 | 实训题目、课程安排和交付要求 | 项目目标、AI辅助开发过程、文档和答辩交付范围 | 实训日程、答辩PPT |
| S02 | 已确认的班级管理业务规则 | 三角色、班级绑定、名单激活、管理员交接、CSV、PDF等硬约束 | 本清单、PRD |
| S03 | 现有原型和日常使用痛点梳理 | 周/日课表、课程详情、搜索、作业提醒、考试倒计时 | 原型评审记录、项目介绍文档 |
| S04 | 产品、开发和测试联合评审 | 权限边界、接口契约、数据模型、异常与边界条件 | PRD、技术架构说明书、tasks.md |
| S05 | 前后端联调和自动化测试反馈 | 冲突检测、事务回滚、错误提示、移动端和文档修正 | 测试报告、审查报告 |
| S06 | 本地验收与演示准备 | 三角色主流程、CSV、PDF、响应式和审计验收 | 测试报告、测试截图 |

## 二、目标用户与核心诉求

| 用户/相关方 | 核心诉求 | 权限边界 |
|---|---|---|
| 学生 | 快速查看本班统一课表、作业、考试和课程详情 | 只能读取本班当前学期数据，不能修改共享数据 |
| 班级管理员 | 低成本维护本班课程、时段、作业和邀请码 | 只能管理本人所属班级，不得跨班操作 |
| 系统管理员 | 管理学期、班级、名单、账号和管理员交接 | 不直接代替班级管理员维护日常课程和作业 |
| 辅导员/班主任 | 确认班级、学生名单和班级管理员人选 | 通过线下流程提供名单和任命信息，不直接开放注册入口 |
| 系统维护人员 | 可重复部署、备份、恢复、审计和排查问题 | 不得查看用户原始密码或邀请码历史明文 |

- **本地验收通过**：功能已实现，并有自动化或浏览器本地验收证据。
- **已确认待验证**：需求已纳入基线，但生产或专项验证尚未完成。
- **不在本期范围**：明确不纳入当前版本，避免误解为遗漏。

## 四、明确不在本期范围

| 编号 | 内容 | 说明 |
|---|---|---|
| OUT-01 | 学生个人作业完成状态 | 本期作业是班级共享信息，不记录个人完成情况 |
| OUT-02 | 学生自行创建或切换班级 | 班级由名单与邀请码绑定，转班仅由系统管理员执行 |
| OUT-03 | 班级管理员开放注册 | 管理员由辅导员/班主任线下确定，再由系统管理员任命 |
| OUT-04 | 微信、短信或邮件推送 | 本期只提供站内提醒，不接入第三方消息服务 |
| OUT-05 | 多校区统一教务排课 | 本项目定位为班级课表助手，不替代学校教务系统 |

## 五、需求变更与追踪规则

1. 新需求先登记来源、使用角色、业务价值、优先级和验收口径。
2. 涉及角色、班级、学期、账号或数据隔离的变更必须先做权限影响评审。
3. 涉及字段和接口的变更同步更新PRD、技术架构说明书、数据库设计和前端调用。
4. 涉及多表写入、覆盖或交接的变更必须说明事务边界和失败回滚策略。
5. 功能完成后更新[tasks.md](tasks.md)，验收结果同步到
   [测试报告](../03_测试验收/测试报告.md)。
6. “已实现”“本地验收通过”“已部署”“已发布”必须分开记录，不以文档存在代替验证。

## 六、待补充的真实用户调研

生产试用前仍建议面向学生、班级管理员和系统维护人员进行小范围访谈或问卷，重点确认：

- 课程临时调课、单双周和节假日补课的实际处理方式；
- 作业提醒的时间粒度和是否需要个人完成状态；
- 学生转班、休学、复学等账号生命周期细节；
- 班级管理员交接的审批和通知流程；
- 手机端课表查看频率、常用浏览器及打印需求。

上述内容尚未形成真实用户调研证据，不影响当前实训版本本地验收，但应作为后续产品化
迭代输入。
